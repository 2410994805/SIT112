Before we dive into the details of data preparation, what is data preparation? The process of transforming and organizing raw data into a format suitable for analysis or machine-learning algorithms is called data preparation. It is not a new topic; we have already seen examples when we talked about pivoting and melting. Sometimes we need to restructure or reshape our data frame so that we can perform certain types of analysis or visualization. These are all examples of data preparation. Data preparation is a crucial step in the data-science workflow because the quality of the data directly affects the accuracy and reliability of any insights or models derived from it. From a broader perspective, data preparation can also include data cleaning. The purpose of cleaning is to prepare our data for analysis, improve its quality, get rid of outliers, or find out why we have outliers so we can make adjustments to our data sets. We talked about techniques for dealing with outliers in the previous lecture, so in a way we are also preparing the data. We separate cleaning and preparation into two processes because cleaning itself is a large enough topic to be discussed separately. In reality, there is overlap between preparing and cleaning, so do not be surprised if some definitions combine the two.

The last part of the lecture deals with a specific warning called the setting-with-copy warning. In computer programming, a warning is not an error; it does not stop code execution. It may not cause a problem, but it might lead to an error in the future, so it is worth investigating how it affects a program or script. Setting-with-copy warning is an important warning when working with data. Documentation links can sometimes be confusing because they are technical, so we will keep the explanation simple. Suppose df equals shots.copy(), creating a copy of the data set. Then df_slice equals df.query(...), extracting rows with a particular game ID. The query operation may create and return a new data frame rather than a view or reference to the original. If so, changes to df_slice do not affect df. Updating the player-name column in df_slice to Curry changes the slice, while the original df still contains Stephen Curry. This does not corrupt the original data, but we may still receive a warning because we do not know whether query returns a copy or a view internally.

01:02:56
The warning tells us to be careful because the behavior depends on how the query function is implemented in pandas, and that implementation could change. We can explicitly call copy after the query. This creates a copy rather than relying on the query function to return one, ensuring that changes to the resulting data frame do not affect the original. If query already returned a copy, the explicit copy only prevents the warning from being displayed. It does not solve a more sophisticated problem by itself, but it protects against a future implementation that might return a view. Without a copy, a slice may be only a pointer or reference to part of the original data frame. Changes made through the slice can then affect the original data. In that case, the data may be corrupted. Calling copy ensures that modifications are applied to an independent data frame.

01:06:15
Here is another example in which the data is corrupted. We create a data frame and then create a slice based on an index, extracting two rows corresponding to particular game IDs. We change the player-name value in the slice to Curry. At first this appears harmless, but the change is reflected in the original data frame as well. This happens because the slice is a view or reference rather than an independent copy. The warning tells us to be careful, since we may not know whether the operation returns a copy or a view until we test it. To prevent the problem, call the copy function when creating the slice. Then changes to the copied slice affect only that copy and not the original data frame. The original data remains preserved and there is no data corruption.

Data corruption can also happen even when we do not receive a setting-with-copy warning, so we cannot rely on the warning to prevent corruption. For example, assigning df_slice equal to df makes df_slice a pointer or reference to df. Any operation carried out on df_slice is reflected in df, even though no warning is displayed. Be careful with this kind of assignment. If you want to prevent the problem, call copy and create an independent copy of the dataset. Otherwise, changing player names in the slice may unintentionally change them in the original data frame. The copy function preserves the original data. Thanks for your attention.
